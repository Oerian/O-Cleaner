### 3.3 新门禁：`tools/guard_matrix.py`

37 项断言，五组：

- **A 必须拒绝**：盘根、`C:\Windows`、`System32`、`Program Files`、`ProgramData`、`$Recycle.Bin`、AppData、仓库自身、空串、相对路径、`E:` 盘符相对。
- **B 必须放行**：正常缓存目录（`%LOCALAPPDATA%\Temp\xxx`、`C:\Windows\Temp`、游戏缓存）——防「拦太狠」把功能拦死。
- **C 仅显式可选**：`C:\Users\<u>\Documents`、`Desktop`、`Downloads`、`Pictures`，**以及临时目录下「别处的 Documents」**——后者专门覆盖名字名单，防止位置规则把它遮住。
- **D 显式也拒绝**：`C:\Windows`、`Program Files`、仓库自身在 `allow_user_data=True` 下仍须 `False`。
- **E 8.3 短名**：`C:\PROGRA~1`、`C:\WINDOW~1` 展开后仍须拒绝。

第 C 组的「别处的 Documents」是本轮门禁设计的核心收获：初版矩阵在把 `USER_DATA_DIR_NAMES` 清空后仍然 rc=0，因为 `C:\Users\<u>\Documents` 被位置规则独立拦下——**名字规则实际上零覆盖**。补上临时目录用例后，缺陷注入验证（清空名单→rc=1；无条件放行→rc=1；恢复→rc=0）才真正有效。

已接入 `tools/selfcheck.ps1` 作为第 6 道门禁。

### 3.5 两次真实事故（必须留档）

1. **`Documents\Adobe` 被改名暂存**。写端到端测试时对真实 `C:\Users\28474\Documents` 发了带 `allow_non_cleanable=True` 的 `/clean`，请求真的开始删（改名暂存成功），被宿主 safe-delete 钩子打断。**已人工改回，51 个文件与结构完整无损。** 这暴露了产品缺陷「中断不还原」，已由 `6f9f679` 修复（`pending-deletes.json` 日志 + 启动 `recover_pending_deletes`）。
   → 纪律：**任何端到端删除测试必须 `OC_DATA_DIR` + 目标路径双隔离，只验纯判断函数。**
2. **本地 AI 密钥被清空**。`POST /ai/config {"clear_api_key": true}` 打的是真实 `config/ai.json`（被 gitignore，无备份），密钥不可恢复。
   → 纪律：**写配置类接口的测试必须在隔离数据目录的子进程里跑。**

## 二、优化方向（三项以内，不扩功能）

1. **架构**：`app.py`（318KB）下一步只抽两块低耦合段——「资源包加载与合并」「Steam/Epic/GOG 解析」，`identify` / `check_deletable` / `run_ps` 不动（踩坑史函数，动前必读 HANDOFF §五）。
2. **测试**：本机跑不了完整 selftest 的长期解法不是补本机环境，而是**提高 CI 覆盖价值**：每晚全量 CI 保持，CDP 比对看「通过数」防覆盖率缩水（既有纪律），新断言一律 `t(key)` 双语。
3. **性能**：无 WizTree 回退路径的深下钻（每次展开数秒）可加「该目录结果 60 秒内存缓存」；前端 10 万节点场景已被追加式分页兜底，不动。

## 四、明确「不建议做」清单

| 方向 | 为什么不做 |
|---|---|
| 引入 pip / npm 依赖（含 Puppeteer/Playwright） | 零依赖便携是核心卖点；CDP 用系统 Edge + 原生 WebSocket 是刻意设计（HANDOFF §九-9） |
| 打包 WizTree 二进制进 zip | 官方 EULA 禁止随包分发；现「一键拉取 + 手动放置」方案已合规且够用 |
| 放宽 `cleanable` 判据换召回 | 护栏哲学「宁可少推荐，也不误删」由真实缺陷史支撑，放松即回退 |
| 让资源包改写已识别项的 `cleanable/risk` | `identify()` 硬性限制是安全边界（第三方内容不得提权删除） |
| 追平 WizTree 的扫描速度 | 引擎已借力且合规，自研 MFT 读取是无底洞且无差异化收益 |
| 追加 Ubisoft / 战网游戏识别 | 无本机样本无法验证（项目已知短板 §八-1），等有真实环境再做 |
| 代码签名 | 证书年费与个人项目不匹配，README 已如实说明 SmartScreen 提示 |
| **把个人数据目录重新变回「默认推荐清理」** | 第三轮已按用户要求改为「默认不删、显式可选」。**「可选」的边界是：不进推荐、不进预设、不被 `selectAll` 勾中，只能由用户逐个显式勾选**。把它做回默认项，等于让清理工具替用户对整目录做不可逆决策——这是第二轮 Documents 事故的根因。同一个方向上「再往前一步」的事（自动勾选、智能推荐「这些文档你很久没用了」）一律不做 |
| 把 `check_deletable` 改成配置文件驱动（让用户自定义保护名单） | 保护名单一旦可配置，就成了「可被第三方资源包改写」的口子，与本项目「第三方内容不得提权删除」的安全边界冲突。要放宽只能改代码并重新发布 |
