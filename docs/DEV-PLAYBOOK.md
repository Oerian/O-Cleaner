# 通用 GitHub 与开发工作规范（Dev Playbook）

> 从 O-Cleaner 开发实践沉淀的通用规范，适用于任何项目。来源：`docs/HANDOFF-PROMPT.md`（阶段 0 / 输出与纪律）、`HANDOFF.md` 编码契约，以及历史踩坑记录。
> 原则：**每条规范背后都有一次真实事故**——不要因为「看起来没必要」而省略步骤。

---

## 一、Git 提交与推送纪律

1. **一个提交只做一件事**。修复、功能、文档分开提交；混合提交让回滚和 review 都失效。
2. **提交信息首行一行说清主题**，不写 `[ci]` 之类标签，不带评价性文字（「优雅地修复了……」这类删掉）。
3. **断言数字和耗时量级不写死**在提交说明或长期文档里（写「失败 0 即绿」「秒级」，不写具体数字——数字随环境漂移，写死即过时）。
4. **推送用 SSH 优先**（晚高峰 HTTPS 可能被按 IP 阻断）；`gh` CLI 用全路径调用（Windows 常见安装位 `C:\Program Files\GitHub CLI\gh.exe`）。
5. **不推送、不触发 CI、不升版本号、不动 Release**——这些是「版本更新」时的既定动作，除非明确要求。日常修复只本地提交。
6. 拿不准的改动**只记录不修**；确认的 P0/P1 才修并提交。

## 二、环境与命令注意事项

1. **服务器重启铁律**：改动任何代码文件后，必须杀掉旧进程再起新进程，并用启动时间核验是刚起的（Windows：`netstat -ano | grep <port>` 找 PID → `Stop-Process` → 重启 → `Get-Process -Id <pid> | Select StartTime`）。脚本语言代码是进程启动时导入的，**旧进程 + 新文件 = 「半新」假象**，这类 bug 控制台毫无征兆。
2. **Bash 工具的工作目录会静默重置**：一律用绝对路径或 `git -C <path>`；管道取退出码必须 `out=$(cmd 2>&1); rc=$?` 的形式，直接接 `| tail` 会丢退出码。
3. **临时文件、探针脚本只放 `$TEMP` 或仓库 gitignore 目录**，绝不落任何盘根（沙箱对盘根写入会静默 EPERM）。
4. **清理测试残留一律走回收站**，绝不用 `rm` / `del` 直删。
5. 长会话开始先校准基线：`git log --oneline -3` + `git status`，工作区应干净。
6. 已知坑位有记录的**不要重复排查**——先读交接/记忆文档。

## 三、失败归因纪律

**把失败归因环境之前，先问「CI 上能不能复现」。** 历史上把真缺陷当环境问题豁免过。判定顺序：

1. 本机复现 → 最小化复现用例；
2. 本机不可复现 → 推 CI 跑（CI 是干净环境的权威裁判）；
3. 只有 CI 失败 → 检查环境差异（权限、盘符、locale、文件系统大小写）；
4. 确认是环境不具备（如无样本数据）→ 断言做**内容门控**（有数据时严格断言，无数据时 skip 并注明原因），而不是删断言。

## 四、验证分工：本机 vs CI

| 层级 | 本机 | CI |
|---|---|---|
| 静态检查（pyflakes / lint / 编码契约） | ✅ 每次改完就跑 | ✅ 每次推送 |
| 合成数据单测 | ✅ 快速子集 | ✅ 全量 |
| 完整 E2E / 长时间套件 | ⚠️ 受宿主限制（配额、权限）跑不完 | ✅ **权威验证** |
| 真实数据探针 | ✅ 只读探针 | ❌ 无真实数据 |

本机跑不完的套件**不硬跑**，交给 CI；但 CI 断言必须做环境自适应（见上节门控）。

## 五、编码契约（多语言仓库）

- `.ps1`：UTF-8 **带 BOM**（PowerShell 5.1 无 BOM 会把中文读成乱码）。
- `.py` / `.json` / `.html` / `.md` / `.js`：UTF-8 **无 BOM** + CRLF。
- 统一用项目的编码检查脚本校验（O-Cleaner 为 `tools/fix-encoding.ps1 -Check`），提交前必跑。

## 六、多轮迭代的 UI/集成测试经验

1. **内容门控优于删断言**：环境相关断言（依赖磁盘上有真实目录、有样本文件）用「数据存在才严格断言」的模式，保护力不降、误报消失。
2. **合成数据先行**：核心解析逻辑（如二进制格式解析）先用合成数据单测覆盖格式要点，真实数据只做端到端冒烟。
3. **CI 环境未必是「干净 Linux」**：Windows runner 默认管理员——依赖权限的代码路径会在 CI 上真实激活，测试必须为此设计（这正是发现引擎第三方兼容性的机会）。
4. **前端文本断言注意空格归一化**：如果测试框架做了空白剥离，断言字符串也要同步去掉空格，否则永远失败。
5. **新增渲染函数必须注册到语言切换的重建清单**，否则切语言后界面残留旧文案。

## 七、性能优化方法论

1. **先基准后改动**：没有 before/after 数字的操作不算优化。基准要固定输入、取多次最优、剔除噪声。
2. **间接层开销可能吃掉算法收益**：lambda/包装函数在每行都执行的热循环里是真实成本——内联直调（局部别名如 `up = struct.unpack_from`）实测可差 20%。
3. **复杂度换微秒收益要审慎**：memoryview 换 bytearray 这类「半兼容」优化，收益 <1s 时直接放弃，保持简单。
4. 每次优化后跑**一致性断言**（新旧实现对同一输入输出必须全等）+ 回归套件。

## 八、会话交接自检清单

- [ ] 基线确认（HEAD、工作区干净）
- [ ] 旧进程已杀、新进程已起、启动时间已核验
- [ ] 静态检查全绿
- [ ] 本机可行的回归子集全绿
- [ ] 改动分主题提交、提交信息合规
- [ ] 测试残留已清理（走回收站）
- [ ] 临时文件在 `$TEMP`（不进仓库、不在盘根）
- [ ] 交接文档（HANDOFF / 记忆）已更新本轮结论
