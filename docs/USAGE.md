## 一、快速开始

1. 确认已装 Python 3（命令行执行 `python --version` 能看到版本号即可）
2. 双击 **`启动 O-Cleaner.bat`**
3. 浏览器会自动打开 `http://127.0.0.1:8770/`

> **那个黑色命令行窗口就是服务本体，清理期间不要关闭它。**
> 关闭窗口 = 停止服务，网页会变成连不上。全部清理完成后关掉即可。

### 免安装版（不需要 Python）

`O-Cleaner-v<版本>-win64-embed.zip` 是**内嵌了官方 Python 运行时**的免安装
版：解压后直接双击 `启动 O-Cleaner.bat`，这台电脑上不需要安装或配置 Python。

- 便携使用：历史记录与配置都写在解压出来的文件夹内，整个文件夹放到任意
  可写目录即可；不要放在 Program Files 这类需要管理员权限的位置。
- `python/` 目录是内嵌运行时，请保持完整，不要单独挪动或精简。
- 首次运行 SmartScreen 可能提示「已保护你的电脑」——本程序未做代码签名，
  点「更多信息」→「仍要运行」即可。卸载就是删除文件夹，不留注册表项。

想清理系统目录（Windows 更新缓存、系统日志等）时，用**管理员身份**运行：
开始菜单搜 `cmd` → 右键「以管理员身份运行」→ 执行

```
cd /d "你的 O-Cleaner 目录"
启动 O-Cleaner.bat
```

命令行参数：

| 参数 | 作用 |
|---|---|
| `--port 9000` | 指定端口（默认 8770，被占用会自动往后找） |
| `--no-browser` | 启动时不自动打开浏览器 |
| `--data-dir D:\oc-data` | 数据存档目录重定向：历史记录、配置、定时任务等运行数据放到指定位置（也可用环境变量 `OC_DATA_DIR`） |
| `--scan-only` | 只打印一份文字版扫描清单，不开服务 |
| `--scan-only --drive D` | 扫描指定盘 |

### 数据存档目录与 U 盘携带

历史记录、磁盘趋势、定时任务、`config\`（含自定义释义与资源包）等**全部
运行数据**都在数据存档目录里，界面右栏「运行环境自检」会显示它的位置：

- **默认跟程序同目录**：绿色便携，整个 O-Cleaner 文件夹放进 U 盘或拷到
  别的电脑，数据跟着走；拔下即带走，不留系统痕迹。
- **程序目录只读或想单独备份数据**：用 `--data-dir <路径>` 或环境变量
  `OC_DATA_DIR` 把运行数据重定向到任意可写位置（U 盘、别的硬盘都行），
  启动日志与自检面板会如实标注「已重定向」。
- **迁移 / 备份**：把数据存档目录整个拷走即可；换机后放回对应位置（或用
  同样的 `--data-dir` 指过去）即完整还原。

自测（300+ 项断言，含真实删除与 HTTP 端到端；条数依机器环境浮动）：

```
python -X utf8 tools\selftest.py
python -X utf8 tools\lint_rules.py --strict      # 规则与资源包门禁
python -X utf8 tools\_lint_selftest.py           # 验证上一道门禁确实能检出缺陷
```

还有一道浏览器检查，需要先启动服务（用系统已装的 Edge/Chrome，无需额外安装）：

```
node tools\cdp_check.js http://127.0.0.1:8770
```

## 二、界面怎么用

打开后会自动扫描当前盘（默认数据盘，上次用的盘优先；只有一块盘时是 C:）。**默认不会删除任何东西，必须你自己勾选。**

### 界面布局与导航

界面分三栏：**左侧栏**（盘符选择、预设、自定义目录、磁盘趋势），
**中间主区**（清理项卡片、全盘占用排行、Steam 游戏库），
**右侧栏**（自检、资源包、AI、统计、规则、历史等折叠面板）。

两个功能页常驻在顶部标签里：**常规清理** 与 **Steam 游戏库**，
点标签即切换，当前页高亮；不需要在多层按钮里找入口。
右侧栏面板较多（十余个），每个折叠面板可点标题展开 / 收起；
侧栏顶部有一条**面板目录**，列出全部面板标题，点击任意一项会展开并滚动到那个面板——
找不到功能时先看目录条，不用逐个展开翻找。
按 `Esc` 可返回上一级（细分查看、下钻层级等），扫描进行中会提示稍后再退。

左侧栏的**磁盘趋势**是本盘近 30 天的可用空间阶梯折线，每个转折点就是一次清理；
鼠标放到转折点附近，会显示那次清理的时间、释放容量与清理后的可用空间。

磁盘概览（容量、使用率、可清理/保留/未识别占比）只出现在扫描概览页一处；
Steam 库信息在 Steam 游戏库页与其左侧卡片，两处各司其职，不重复堆叠。

### 主题
顶部导航旁有「亮 / 暗 / 随」三个小按钮：白天模式、黑夜模式、跟随系统。
偏好存在浏览器本地，「随系统」会随操作系统的深浅色设置实时切换；
趋势图画布的颜色取自主题变量，切换后立即重画。

### 界面语言
主题按钮旁有 `A / 中 / EN` 三个小按钮：`A` 跟随浏览器语言
（浏览器不是中文环境就显示英文），`中` 与 `EN` 强制指定。
偏好存在浏览器本地，刷新后保持。中文是源码默认文案；
界面骨架、动态文案（徽章结论、提示、面板标题、排序与视图标签、
确认弹窗、磁盘概览与趋势图标签）与知识库长文本（内置规则与
资源包释义的「是什么 / 怎么处理 / 提示」、风险与置信度标签、
分类短词）均已双语，英文界面下扫描结果自动显示英文说明；
切换语言即时生效并重新拉取数据。

### 自定义释义与结论
带目标标注的行点「详情」打开的弹窗里有「自定义释义」按钮：可以改写这项的
「是什么 / 能否重建 / 删除影响 / 建议保留」四段说明，也可以把结论
改成「可清理」或「不可清理」。改过的项在详情里能看到新说明，
改了结论的「全选」与勾选会跟着新结论走。

- 优先级：**你的修改 > 资源包 > 内置说明**；「恢复默认」一键还原。
- 普通清理项按类型生效（跨盘符通用）；「自动发现」的目录按具体路径生效。
- 把高风险项改成「可清理」不会降低风险等级：清理时仍按高风险处理
  （默认删进回收站）。
- 数据存在 `config\custom-overrides.json`（本机文件，不随仓库分发），
  随整包拷贝到别的电脑时一并带走。

### 选盘
顶部右侧是盘符卡片，显示每个盘的可用空间和占用比例。点一下切换。
每个盘的目标列表不同：

- **系统盘（C:）** 包含 `Windows\Temp`、更新缓存、Prefetch、Minidump 等系统项
- **数据盘（D:/E:）** 只有该盘真实存在的东西，不会列出 `D:\Windows\Temp` 这种空项
- **自定义目录** 在工具栏输入任意路径（如 `E:\GameCache`），会扫描其中已知的垃圾文件夹

### 清理范围
工具栏的「清理范围」决定列表包含什么：

| 选项 | 含义 |
|---|---|
| 当前盘 + 用户级缓存 | 除了本盘专属项，还包括与盘符无关的用户级缓存（uv / pip / 浏览器缓存等，位于 `%LOCALAPPDATA%`） |
| 仅当前盘专属项 | 只看和所选盘直接相关的项，例如 `D:\Temp`、`D:\$Recycle.Bin` |

选中数据盘（D/E…）时，「仅当前盘专属项」为默认值：`%LOCALAPPDATA%`
始终展开为系统盘上的用户目录，这类项目与所选盘无关，出现在 D 盘清单中只会造成
「D 盘为什么有浏览器缓存」的疑问；它们在 C 盘清单中同样存在。

（早期版本未做此过滤，选中 D 盘会看到「D 盘的 pip 缓存」而路径为 `C:\Users\…`。
该问题已修复，自检中有一条断言固定此不变量：非系统盘的目标路径必须位于该盘。）

### 自动发现（数据盘能用的关键）

预定义目标只覆盖常见系统位置（`Windows\Temp`、回收站等），但磁盘占用的大头
往往是**长尾的个人软件**。所以常规扫描还会主动在本盘顶层寻找
「被知识库识别为可清理」的目录 —— 这类项带橙色的「自动发现」标记。

自动发现能覆盖到的内容取决于该盘实际装了什么，例如网盘缓存、音乐软件缓存、
驱动包、Office 部署缓存、下载器缓存等 —— 这些目录在预定义清单里没有对应条目，
不主动查找就不会出现在列表中。

自动发现的安全约束：

- 只接受知识库判定为**可清理**且置信度非低的候选；未识别的一律跳过（宁可少提示，也不猜）
- 排除回收站内部（`$Recycle.Bin\S-1-5-...` 这类 SID 目录没有解释价值）、
  `ProgramData`、`AppData`、`Windows` 等位置
- **排除 `Program Files` / `Program Files (x86)`** —— 那里面是程序本体不是缓存
- **排除「装的是程序」的目录**：见下面这条
- 同名的父/子目录只保留最外层，避免 `steam` 与 `steam\appcache` 同时出现
- 父目录本身就是可清理候选时，不再逐个推荐它的子项
  （否则下载目录下的剪辑草稿目录会被当成 8 个独立清理项推荐，
  而那里面是用户自己的作品）
- 最多 12 项、深度最多两层 —— 清单太长反而让人无从下手

#### 「这目录里装的是程序」怎么判断

自动发现是按目录名命中知识库的，而知识库的关键词是给缓存目录写的，
因此可能命中安装目录。已知的例子：

- 名字里含短词 `ps` 的目录会命中 photoshop 规则，而这类目录也可能是
  Adobe 系列软件的安装目录
- `C:\Program Files (x86)\Adobe`、`C:\Program Files\Microsoft OneDrive`
  也曾被判成可清理

所以增加了一道只看通用特征、不看名字的判断（看名字正是问题所在）：

| 判据 | 说明 |
|---|---|
| 顶层有 `Uninstall*.exe` / `unins*.exe` | 安装器留下的卸载程序 |
| 两个以上「版本号形态」的子目录 | 年份（如 `Photoshop 2024`）或四段式版号（如 `WPS Office\12.1.0.x`） |

刻意不采用的两条判据：

- 「顶层 .exe 数量」—— 下载目录顶层常有多个 `setup.exe`，
  按数量计算会把下载目录误判成程序安装，丢掉一个有用的候选
- 「子目录里有卸载程序」—— 下载目录下已安装过的软件目录都带卸载器，同样会误伤

卸载程序只在顶层出现才计入。原则是宁可少提示，也不把「卸载软件」当成「清理缓存」推荐出去。

### 一键预设
右侧「一键预设」，最常用的是**安全清理**：只选「删掉会自动重建」的项，
跳过回收站、着色器缓存和需要管理员权限的项。

| 预设 | 作用 |
|---|---|
| 安全清理 | 缓存与临时文件，最稳妥 |
| 深度清理 | 再加显卡着色器缓存、缩略图、崩溃转储、系统日志 |
| 开发者清理 | 只清 uv / pip 包缓存 |
| 只清回收站 | 只选回收站，可展开挑单个大文件 |
| 全部取消 | 清空勾选 |

### 看清再删
占用排行里每行右侧的 **`详情`** 打开完整说明：**识别为 / 分类 / 风险等级 /
识别依据**，加 **是什么 / 清理建议 / 完整路径**。
例如 pip 缓存的「建议保留」写的是「常用离线安装，或经常重装同一批依赖」。
判定为「可清理」的行左侧有勾选框，勾上即计入底部「已选 / 预计释放」。

### 自动全盘扫描（一键直达，默认展示全盘最大项目）

点击工具栏的 **`全盘扫描本盘`** 即可**自动开始扫描**，无需二次点击。
扫描完成后，视图默认直接呈现 **「全盘最大项目」**，按实际占用体积降序直观展现空间大头；
同时也支持按需切换到「本层目录」、「只看文件」或「全部可清理」。

### 扫描深度：快速与深扫

`全盘扫描本盘` 旁边的下拉框选择扫描深度：

| 档位 | 行为 | 适用 |
|---|---|---|
| 快速（默认，1 层） | 只展开 1 层（各首层目录的体积），先看清占地大头；**游戏本体始终出现在排行里**（不受深度限制）；更深的目录在结果里仍可点击下钻（现场扫描，稍慢） | 绝大多数场景：先定位大头再按需下钻，比一上来就深扫快得多 |
| 深扫 | 沿体积最粗的分支逐层展开（最深 5 层），直接挖到深层大项 | 想一次看全深层占用；装了 WizTree 时代价很小 |

选择会记住（刷新后保持），默认为**快速**。扫描中途切换档位会作废旧扫描、
按新档位重新开始；快速模式的扫描结果在面板上标注「快速（1 层）」。
注意：快速模式仍需测量各首层目录的体积（这是扫描的主要开销），
无 WizTree 时它比深扫省下的是「深层下探」的部分，不是秒级速览。

### 重复项与勾选去重：同一项目整删不拆

占用排行里可能出现「大项和子项包含相同内容、体积近似」的重复行。处理规则：

- **游戏本体（Steam / Epic / GOG）是同一项目，整删不拆**：本体行出现时，
  它内部的子项不再单独上榜；若同时勾选本体和内部某项，只会整目录删除本体。
- **压缩包、download 等可拆分目录**：子项照常显示、可以单独勾选；若外层与
  内层同时被勾选，只清理最小项，不重复删除、预估体积也不会翻倍。
- 被跳过的重复项会在清理结果里如实说明（「已在同一游戏本体内，整删不拆分」
  /「已包含更小的勾选项，只清理最小项」）。

### 起始盘与扫描提速

- **起始盘默认数据盘**：打开界面时自动选第一个非系统盘（上次用的盘优先）。
  系统盘小文件极多、扫描最慢，清理的主战场通常也在数据盘；只有一块盘时维持 C:。
- **换盘秒开**：每个盘 10 分钟内的全盘扫描结果会被缓存，来回切盘直接展示
  （面板标注「N 分钟前的扫描结果」）；点「全盘扫描本盘」强制重扫，清理后缓存自动作废。
- **系统盘想扫得快**：装 WizTree（界面可一键下载便携版）走 MFT 读取，
  或把档位保持在「快速」。

### 细分查看：这个目录里到底哪块能删

在「全盘扫描」里点开一个目录的详情，底部有 `细分查看：哪些能删`。它把一个目录拆成两部分：

| | 内容 | 举例 |
|---|---|---|
| ① 可清理的缓存子目录 | 删掉会自动重建的派生数据 | `Cache`、`Code Cache`、`GPUCache`、`Service Worker` |
| ② 不要删除 | 用户数据与程序本体 | 书签、密码、Cookie、`History`、`Extensions`、游戏资源包 |

需要它的原因是：一个与浏览器同名的目录可能占用上百 GB，整体标成「可清理」会连书签和密码一起删掉，
而只写一句「建议保留」又无法说明这上百 GB 里哪些部分可以动。因此这里逐个子目录给出体积和理由。

它会先判断目录的实际身份，再决定给出什么结论：

- 浏览器资料目录：提示其中有书签与密码，缓存部分单独列出
- 游戏安装目录：提示这是游戏本体，可清理字节固定为 0，回收空间请用 Steam 卸载
- 无法确定身份：明确写出「工具不判断」，只列出体积分布，不给结论

判定不依据目录名。同名目录中也可能存放论文、ComfyUI 归档等用户内容，
只看名字会误报「这里有你的书签和密码」。因此需要在目录内实际观察到 `Cache` / `User Data`
这类结构，才判定为浏览器资料目录。

### 确认与执行
点右下角红色「清理选中项」→ 弹出确认表格，逐项列出**确切路径、大小、文件数**，
中/高风险项和不可逆操作会红框警告，权限不足的项会被点名 →
点「确认删除」才开始。完成后报告**实际释放量**（不是预估）和跳过原因。

被浏览器、剪辑软件占用的文件会**跳过而不是报错**，并提示「关闭相关程序后重试」。

### 文件被占用，删不掉怎么办

清理结果里只要有「已跳过」的项目——或者某项因为占用被**整体中止**（一个都没删）——弹窗中就会多出一个 **「一键查找占用进程」** 按钮。点一下，它会做两件事：

1. **逐个确认**这些文件现在是不是真的被占着（这一步是可靠判定）；
2. 列出**可能占用它们的程序** —— 进程名、PID，以及「凭什么认为它可疑」。

**它只列候选，不会替你关任何进程。** 道理很实在：Windows 没有公开接口能把「文件句柄」反查成「进程」，所以第 2 步是**启发式猜测**，可能有遗漏、也可能有误报；而关错进程可能丢掉别人没保存的文档。判断和动手都交给你。

看到可疑程序之后：**先在那个程序里保存并退出**（多数程序一退出就自动解锁），再回到本页重新清理即可。

一个候选都没有也很正常，这时用系统自带的排查工具：
**任务管理器 →「性能」 → 左下角「打开资源监视器」 →「CPU」 → 展开「关联的句柄」 → 搜索框里输入文件名**，就能看到真正持有它的进程。

> `System`、`explorer.exe` 这类系统进程不要结束。

**已知持有者的捷径**：有些文件注定在进程列表里搜不到 —— 比如 `Windows 更新交付优化缓存` 的 `content.bin`，它由「传递优化」服务（DoSvc）寄在 `svchost.exe` 里持有，命令行里没有路径、程序本体也不在缓存目录。遇到这类情况弹窗会直接给出提示：管理员 PowerShell 执行 `Stop-Service DoSvc` 后回来重新清理，清完 `Start-Service DoSvc` 恢复（重启电脑也会自动恢复）。

### 侧栏面板：折叠堆叠与独立滚动

右侧栏的面板默认折叠成一行标题，点击标题展开或收起，展开状态记在浏览器本地（键名 `oc.acc.v1`），刷新后保持。

左右两栏各自独立滚动：滚左侧清单不会带动右侧面板，反之亦然。窗口宽度小于 1180px 时改为整页滚动，避免两栏都被挤得过窄。

标题里带按钮的面板（例如「运行环境自检」里的下载按钮）点按钮不会触发展开/收起。

### Esc 键：返回上一级

- 有弹窗时：关闭弹窗
- 在占用树里：退回上一层目录；已在顶层时提示「已在顶层目录」
- 在「Steam 游戏库」页：回到扫描概览
- 扫描进行中按 `Esc` 不会打断扫描，只提示等扫描结束

### 资源包：补充与改写清理项释义

侧栏「资源包」面板列出当前加载的资源包，每个包显示条目数、类型与来源（内置 / 用户），可单独启用或停用。

| 操作 | 说明 |
|---|---|
| 导入资源包 | 选择本地 `.json` 文件，校验通过后写入 `config/packs-user/` |
| 从 GitHub 检查更新 | 按远端 `packs/index.json` 逐个下载并导入；与内置包同 id 时覆盖内置版本。默认远端是公开的 [O-Cleaner-packs](https://github.com/Oerian/O-Cleaner-packs) 仓库，也可在界面上改成自己的地址 |
| 启用 / 停用 | 停用后该包不参与识别，内置清单立即生效（无需重启） |

匹配与覆盖规则：

- 包条目用「路径片段」匹配目录或文件，可以要求全部命中（`all`）或任一命中（`any`）
- 多条条目同时命中时，**匹配位置更靠路径末尾的优先**，其次比匹配串长度。这条规则是为了让叶子目录（如 `steamapps\shadercache`）不被容器目录（如 `\steamlibrary\steamapps`）盖掉
- 内置知识库**已识别**的项目：包只能改写说明文字（是什么 / 能否重建 / 删除影响 / 建议保留）与显示名，`可清理` 与 `风险` 仍以内置规则为准
- 内置知识库**未识别**的项目：包可以给出完整结论，包括是否可清理与风险等级
- 修改或导入后立即生效，刷新页面即可看到

包格式与编写规范见仓库内 [packs/README.md](../packs/README.md)。

### 接入自有 AI（可选）

侧栏「AI 助手」面板用于接入你自己申请的大模型接口。**不填就完全不工作**，程序也不会因此发起任何网络请求。

| 配置项 | 说明 |
|---|---|
| 接口地址 | 任何 OpenAI 兼容的 `chat/completions` 接口，填到 `/v1` 这一级即可；面板里有 **DeepSeek / Ollama（本机）** 预设按钮，点一下就填好 |
| 模型名 | 可手填，也可点 **「获取列表」** 自动识别该接口的可用模型，从下拉建议里选 |
| API Key | 保存在 `config/ai.json`（已在 `.gitignore` 中，不会进版本库） |
| 温度 / 超时 | 可调；默认 0.2 / 60 秒 |

**快速接入（以 DeepSeek 为例）**：platform.deepseek.com 注册并创建 API key → 面板点「DeepSeek」预设填好接口 → 粘贴密钥 → 点「获取列表」→ 选一个模型（日常用 `deepseek-chat`，推理模型是 `deepseek-reasoner`）→ 勾「启用」→「保存」→「测试连接」。面板里常驻这五步引导；本机 Ollama 无需密钥，点对应预设即可。

两个用途：

1. **解释单项**：在详情弹窗里点「让 AI 解释」，AI 结合该项的真实路径、体积与内置说明给出通俗解释
2. **生成清理方案**：用自然语言提要求（例如「只清不重装就能重建的缓存，别动游戏」），AI 返回一个候选列表

安全边界：待选清单只包含**已被内置规则判定为可清理**的项目，AI 返回的未知 id 会被丢弃并在结果中列出；AI 无法执行删除，方案只会替你勾选复选框，最终仍需你确认后走底部按钮的同一套删除流程。

**把 AI 方案沉淀成规则**：AI 替你勾选之后，如果这套勾选以后还会反复用，点「自定义规则」面板里的 **保存当前勾选为规则**，给它起个名字 —— 以后一键套用，不用再问一次 AI。整条链路是：AI 提方案 → 替你勾选 → 你满意就存成规则 → 下次一键执行；每一步都有人确认，AI 自始至终碰不到删除按钮。

界面对 Key 只回显尾 4 位，完整 Key 不会通过任何接口返回。

## 三、Steam 游戏库（读清单，秒级）

右侧「Steam 游戏库」面板**不扫描磁盘**，而是直接读 Steam 自己的清单文件：

- `steamapps\libraryfolders.vdf` —— 列出所有 Steam 库（可跨多个盘）
- `steamapps\appmanifest_*.acf` —— 每个游戏的名称、安装目录、体积、状态、最近游玩时间

读取这些清单不需要遍历磁盘，因此耗时只与库中游戏数量相关，与磁盘体积无关。

面板显示：游戏数、Steam 记录的总体积、每个库的位置与占用；游戏列表可按
**「最久没玩」或「按体积」**排序，并直接标出 `某游戏 13.9 GB · 从没玩过`
这类信息 —— 这是「该卸载哪个」最直接的答案。每条都有「打开目录」按钮。

两个只有读清单才能做到的事：

**① 与扫描结果互相印证。** Steam 记录的体积（`SizeOnDisk`）是它自己算的，
可以拿来对照磁盘实际占用；面板还会列出**磁盘上存在但 Steam 已无记录的残留目录**，
这类「卸载不干净」的残留通常是最值得回收的空间。

**② 状态校验。** 读 `StateFlags` 位判断游戏是否真的装全了
（1=未安装、4=已安装、2=更新中等），不会把「更新到一半」的游戏当成完整安装。

> 释放游戏空间的两种方式：**在 Steam 客户端里卸载**（右键游戏 → 管理 → 卸载，
> 它会一并清理库记录，不留残留），或者在本工具里**点开游戏 → 「删除这个游戏」**
> 直接删除整个安装目录（见下文）。两种都能回收空间，前者更干净。

### 游戏是可清理项：直接删除整个游戏目录

游戏本体（Steam / Epic / GOG）在界面里标为**「可清理」**——没在玩的大作就是
一台机器上最值得回收的空间，动辄几十 GB。操作方式：

1. 在 **Steam 游戏库**页面（或全盘扫描的占用树里）点开某个游戏；
2. 详情弹窗会显示**中文名**、占用体积、完整路径，以及存档风险说明；
3. 点红色的**「删除这个游戏」**，确认弹窗再次列出后果后才执行。

删除是**永久性的**（不进回收站），因此确认弹窗会明确写出：

- 删的是**整个游戏目录**，包括放在目录里的存档、配置和 Mod；
- 多数游戏的存档其实在 `文档\My Games`、`AppData` 或平台云存档里，**不受影响**；
- 更稳妥的做法仍是在客户端里卸载；直接删目录后客户端里会显示「未安装」，
  想再玩重新下载即可。

**安全边界**：删除走的是专用接口 `POST /__oc__/clean-game`，它**不是**通用删除
接口 —— 路径必须被**后端自己**识别为游戏安装目录（`steamapps\common` 的直接
子目录，或 Epic / GOG 清单里的精确安装路径），再过一遍系统目录保护
（System32、盘符根、相对路径、空路径等一律拒绝）。前端传什么都绕不过这道校验。

### Steam 游戏也整合在「全盘扫描」里（支持中文名显示）

不必在「磁盘空间」和「Steam 面板」之间来回对照：扫描时会读一次 Steam 清单与 `config/game-names.json` 映射表，
在占用树和 Steam 页面中直接显示中文游戏名：

- `荒野大镖客：救赎 2（Red Dead Redemption 2）`
- `天国：拯救 2（Kingdom Come: Deliverance II）`
- `巫师 3：狂猎（The Witcher 3: Wild Hunt - Complete Edition）`
- `底特律：化身为人（Detroit: Become Human）`
- `文明 6（Sid Meier's Civilization VI）`

游戏直接列入「全盘最大项目」与当前层列表，不再设独立生硬的「游戏等大项」分类，
也去掉了「第 N 层」等无关的内部层数标注，界面更加干净直观。
游戏本体标为**可清理**（`cleanable=true`，风险等级「高」）——因为没在玩的游戏
正是最该回收的空间；详情弹窗会讲清楚删掉意味着什么，删不删由你决定。
想补充或修改游戏中文名：直接编辑 `config/game-names.json`，纯显示用途，零副作用。

## 四、扫描速度：可选使用 WizTree 加速

全盘扫描有两条路径，检测到 WizTree 时使用快的那条：

| | 方式 | 特点 |
|---|---|---|
| 默认 | PowerShell 递归遍历 | 不依赖额外组件，可扫描任意目录 |
| 加速 | 调用 WizTree 读取 NTFS MFT | 仅适用于 NTFS 卷；耗时取决于磁盘类型与文件数量 |

具体耗时取决于磁盘类型（机械盘 / SATA SSD / NVMe）、文件数量与目录深度，因此不给出固定数值。

### 进度条怎么算的

扫描进度按**真实阶段**上报，不再按时长估算。下表里的百分比都是**整体进度**，不是阶段内进度：

| 阶段 | 进度 |
|---|---|
| 用 WizTree 读取磁盘 MFT 明细 | 不确定（流动条纹） |
| 解析导出明细 | 按已读取字节数：14% → 70% |
| 按体积展开目录树 | 固定值 72%（单步完成，不再细分） |
| 递归统计目录体积（未装 WizTree 时的兜底路径） | 按节点预算：10% → 72% |
| 读取 Steam 库清单 | 不确定（流动条纹） |
| 读取 Epic / GOG 游戏清单 | 不确定（流动条纹），固定 78% |
| 逐项识别与标注 | 按已处理节点数：84% → 94% |
| 整理可下钻信息 | 固定值 96% |
| 完成 | 100% |

「不确定」用于无法预知总工作量的步骤（读 MFT、读游戏清单），
此时显示流动条纹并在下方注明「这一步无法预知总工作量」。这样做的原因是：
早先版本用 `1 - e^(-t/90)` 这类按时间衰减的公式估算，磁盘越快、进度涨得越慢，
与实际进度对不上；扫描卡住时进度还继续爬升，反而掩盖了问题。

因此出现「百分比不动、条纹在动」是正常的 —— 说明当前这一步拿不到分母。
另外，服务端对 PowerShell 调用设有超时，超时后必定返回错误并继续后续阶段，
不会无限期停在同一阶段。

加速路径的原理是不自行解析 MFT —— 那需要管理员权限，并要处理 USN 日志与碎片，
出错时会得出错误的体积 —— 而是调用 `WizTree64.exe` 的导出参数交给它完成：

```
WizTree64.exe D:\ /export="%TEMP%\oc-wiztree-D-1234.csv"
```

### 新用户引导与跨设备便携化

首页右侧栏最上方设有「运行环境自检」面板，新用户或把文件夹拷到新电脑时可确认：

1. Python 运行环境是否就绪
2. 管理员权限是否具备（未提权时说明影响范围）
3. WizTree 加速组件状态：
   - 若系统已安装：直接调用；
   - 若未安装：面板提供「一键下载 WizTree 便携版（约 7.5 MB）」按钮，
     从官方地址下载便携版并解压至本目录 `portable\WizTree\`。

解压后的 `portable\WizTree\` 随整个 `O-Cleaner` 文件夹移动，
拷入 U 盘或传给其他设备时无需重新下载，也不需要管理员权限，不写注册表。

### 附带的好处：任意层级的「拆分二级目录」

WizTree 导出的 CSV 含每个文件的完整路径，且目录行的体积已包含全部子孙目录。
因此解析完成后即得到一张常驻内存的「目录 → 体积」表，任意目录的子项拆分都是查表操作：

```
D:\某缓存目录                  → 17.9 GB
  └ webui                    → 14.9 GB   ▸ 可继续展开
      └ sd-webui-aki-v4.11…  → 14.4 GB   ▸ 可继续展开
          └ python           →  8.4 GB   ▸ 可继续展开
```

每层返回是一次查表操作，深度不受扫描树的层数上限约束，
因此不会出现「树只展开到第 5 层、更深的大项点不开」的情况。

子项很多时（比如某目录下平铺上千个文件），展开不会一口气全塞进页面：
先显示前 50 条，点「显示更多」每次追加 50 条；
若该层子项总数超过了单次返回上限，会如实提示「该层共有 N 个子项，按体积只列出前 M 个」。

## 五、累积清理与换算

**这两块是合并在一个面板里的**（「累积清理与换算」）：

顶部是累计释放总量与清理次数；下面紧接着就是把总量换算成日常单位的卡片
（手机照片 / 1080p 电影 / 4K 电影 / 3A 游戏……），一眼就能感知「清出来的空间能干点什么」。

想深挖细节时展开「查看明细图表」，里面才是：

- **各盘分布** 每个盘各释放了多少
- **趋势图** 每次清理的释放量柱状图（左旧右新，鼠标悬停看详情）
- **按类别累计** 包管理器 / 浏览器 / 临时文件 / 显卡缓存……各占多少
- **贡献最多的项目** 哪些清理项贡献最大

数据存在 `data\history.json`（最多保留 200 次）。「最近清理记录」面板里可一键清空，
清空后累计统计一并归零。

## 六、换算单位（可自定义）

| 单位 | 折算基准 |
|---|---|
| 张手机照片 | 3.5 MB |
| 首 MP3 歌曲 | 8 MB |
| 份办公文档 | 256 KB |
| 部 1080p 电影 | 2 GB |
| 部 4K 电影 | 20 GB |
| 个 3A 游戏 | 48 GB |
| 小时 1080p 视频 | 3 GB |
| 个安装包 | 512 MB |
| 小时 4K 流媒体 | = 4K 电影的 1/3（表达式范例） |
| GB | 换算基准，不单独展示 |

顶部胶囊按钮可以只看某一个单位，或看全部。

### 怎么加自己的单位

界面里直接加：**名称** + **大小**（数值 + MB/GB/TB）→ 点「添加单位」。
不想手填就点「**填入范例**」，会自动填成「部 演唱会录像 = 8 GB」。

也可以直接编辑 `config/convert.json`。这个文件在代码注释里说明了每个字段，
重点是 `bytes_per_unit` —— 它既能写数字，**也能写引用其它单位的表达式**：

```json
{
  "id": "hour_4k_netflix",
  "label": "小时 4K 流媒体",
  "plural": "小时 4K 流媒体",
  "bytes_per_unit": "1/3 * movie4k",
  "note": "4K 流媒体约 7 GB/小时，这里用『4K 电影的 1/3』演示表达式换算",
  "category": "影音"
}
```

上面这段引用了 `movie4k`（20 GB），自动算出 ≈6.7 GB，不用手算。
`unlimited: true` 的单位（如 `gb`）不参与「装得下几个」的展示，只当换算基准。

改完 `config/convert.json` **刷新网页即可生效**，不用重启服务。

## 七、自定义规则（勾选固定项，一键套用）

规则不是「填路径」，而是**把你勾选的那一组清理项存下来**，以后一键复用。

用法：

1. 在占用排行里勾选你想要的清理项（对应清理目标的行；也可以用一键预设勾），可以任意组合
2. 在右侧「自定义规则」面板里给规则起个名字，例如「每周清缓存」
3. 点「保存当前勾选为规则」

保存后规则卡片上会显示：包含几个清理项、**按当前盘算能释放多少**、以及各项的名称标签。
四个操作：

| 按钮 | 作用 |
|---|---|
| 套用到勾选 | 把这条规则里的项重新勾上（不执行删除），你可以先核对再点底部清理 |
| 立即清理 | 直接按规则清理这批项，弹出确认框显示预计释放量后才执行 |
| 改名 | 重命名规则 |
| 删 | 删除规则（只是删规则，不影响任何文件） |

**保存后立即清理**：勾选面板里的这个选项后，点保存时会先问你一句
（显示将清理几项、预计释放多少），确认后立刻执行清理，一步到位。

几个设计细节：

- 规则**记录创建时的盘符**。在 D 盘创建的规则切到 C 盘后「套用/立即清理」会置灰，
  并标注「N 项不适用于当前盘」，避免用错盘的路径去删东西。
- 同名保存会**覆盖**原规则，不会重复堆积。
- 规则是「选择集」而不是清理目标 —— 所以它不会出现在主列表里，只在侧栏出现。
- 规则存在 `config/custom-rules.json`。

### 自定义数据包：一次导出 / 导入三类自定义

面板底部的「导入 / 导出自定义数据」把三类东西打包成一个 JSON 文件：
**换算单位 + 释义/结论覆盖 + 固定项规则**。用途：

- **换机迁移**：导出带走，在新机器导入即还原（建议配合整目录拷贝）；
- **让 AI 生成**：把 [docs/CUSTOMIZE.md](CUSTOMIZE.md) 的格式规范（或你导出的文件）
  发给任意 AI 助手并描述需求，拿到 JSON 后导入。导入逐项校验，
  字段错误或引用了不存在的清理项会被跳过并说明原因——把原因发回给 AI 修正再导即可；
- **备份**：改动自定义项前先导出一份。

导入不会留下半成品：整包先验证格式，三小节内部逐项独立收下，结果有明确报告。

### 贡献规则前请先跑 linter

`config/filetypes.json` 是全盘扫描的识别知识库，其中的规则决定哪些目录会被判定为可清理。
因此提交规则之前必须通过安全闸门：

```
python -X utf8 tools/lint_rules.py            # 本地检查
python -X utf8 tools/lint_rules.py --strict    # 警告也视为失败（CI 用这个）
```

linter 会做八项检查：结构校验、资源包结构、语义自相矛盾检测、关键词跨规则冲突、
使用真实识别引擎验证每个关键词的归属规则、文档与配置一致性、内嵌脚本模板的括号配平，
以及列出所有「可清理」规则供人工复核。其中语义冲突与关键词冲突两项最能发现实质问题 ——
例如同一个关键词被两条建议相反的规则共用。

## 十、支持哪些盘 / 能不能换电脑用

**支持所有盘符**（C: 到 Z:），也可以扫描任意自定义目录。

路径全部使用 `%LOCALAPPDATA%`、`%USERPROFILE%`、`%DRIVE%` 这类变量，
**不写死盘符，也不写死用户名**，所以：

- 整个 `O-Cleaner` 文件夹拷到 U 盘 → 拷到另一台 Windows 电脑 → 双击 bat 就能用
- 那台电脑的盘符、用户名、可用空间都会自动识别
- 唯一要求：装了 Python 3（不需要 pip 安装任何包）

数据盘上不存在的系统项（如 `D:\Windows\Temp`）会被自动过滤掉，
前提是程序能判断该盘是否为系统盘（检查 `\Windows\System32` 是否存在）。

## 十一、安全设计

以下删除目标会被硬性拒绝，即使 `config/targets.json` 被修改：

- 盘符根目录本身，以及在根目录直接删除文件
- `Windows`、`Program Files`、`ProgramData`、`Users`、`Recovery` 等系统目录
- 任何层级出现的 `System32`、`SysWOW64`、`WinSxS`、`Installer`、`servicing`、`Boot`
- `$Recycle.Bin`、`System Volume Information` 目录本身（回收站走专用清理接口）
- 用户主目录 `%USERPROFILE%` 及 `%USERPROFILE%\AppData`
- 非绝对路径（如 `C:`、`..\Windows`、`/etc`）—— 这类输入会被解析成当前工作目录，
  因此直接拒绝

不列入清理建议的内容包括：用户文档、图片、桌面文件、已安装程序本体、已下载的 AI 模型
（如 `.ollama\models`）、`Windows\Installer` 与 `WinSxS` 组件存储。

删除为直接删除，不经过回收站。执行前会弹出确认窗口，列出确切的路径与大小。
完整的护栏清单与对应的回归断言见 [SECURITY.md](../SECURITY.md)。

### 解析层的契约：原样返回，不替调用方猜形状

`run_ps()` 执行 PowerShell 后原样返回解析出的 JSON：脚本输出对象即为 `dict`，输出数组即为 `list`。

这条契约对应一处不易察觉的缺陷：早先的实现写成「结果是数组就取第一个元素」，
而目录体积测量的 PowerShell 恰好返回 `[{path,size},…]` 数组。其后果是细分查看中
除第一个以外的目录体积全部显示为 0，看起来像未扫到，实际是解析层把数组截断了。

结论是：解析层不替调用方猜形状，需要归一化时由调用方显式完成。
`tools/selftest.py` 阶段六用一条断言固定「2 个路径 → 2 个结果」，防止该缺陷复现。

## 十二、常见问题

**Q：启动后网页打不开？**
看黑窗口里打印的「界面地址」那一行，端口可能不是 8770（被占用时会自动往后找）。

**Q：某个项目提示「需要管理员权限」？**
这是正常的，不是错误。`Windows\Temp`、`Windows\Logs\CBS`、更新下载缓存等
本来就需要管理员权限。用管理员身份重新运行 bat 即可。权限不足时
**同批次其它项仍会正常清理**，不会因为一项失败而中断。

**Q：提示「X 项被占用」？**
浏览器、剪辑软件、Python 进程正在使用这些文件。关掉相关程序再清理一次即可。

**Q：清理后游戏变卡了？**
如果清了「NVIDIA 着色器缓存」，游戏首次启动需要重新编译着色器，会短暂卡顿，
之后自动恢复。这是唯一副作用，不会损坏游戏。

**Q：修改配置要重启服务吗？**
不需要。所有 `config\*.json` 改完刷新网页即可生效。

**Q：怎么彻底重置？**
删掉 `data\`（或其中的 `history.json`、`schedule.json`）与 `config\custom-rules.json`，
再把 `config\convert.json` 恢复到默认内容，就是全新状态。
